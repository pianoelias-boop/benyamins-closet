# Benyamin's Closet

A tiny static shop of the pieces Benyamin has saved for himself: menswear with wide legs and double pleats,
seersucker and herringbone, Japanese denim, knits with a pattern, and shoes that might actually be comfortable.
Filters, a saved list, a daily check for sales at the stores, each store's return terms, and no backend.
Everything is plain HTML, CSS and JavaScript, so it runs from any static host.

Live at **https://pianoelias-boop.github.io/benyamins-closet/** (repository `pianoelias-boop/benyamins-closet`).
To update the site, commit and push to `main`; Pages redeploys within a minute or two.

Started 2026-09-20 from Becca's Closet (`pianoelias-boop/beccas-closet`) by following its `MAKE-YOUR-OWN.md`.

## Files

- `index.html`, `styles.css`, `app.js` — the site
- `config.js` — everything personal: names, texts, the email address, the occasion tags, the notebook settings
- `theme.css` — every colour and font
- `icons/`, `manifest.json` — the home-screen icon and web-app manifest, generated by `build/make_icons.py` from the
  emoji in `config.js` and the colours in `theme.css`; rerun it if either changes
- `data.js` — the catalog (generated by `build/make_data.py` from `build/extras.json`)
- `images/full/` — one photo per piece
- `build/` — the scripts: `add_pieces.py` reads `pieces_to_add.csv` and adds pieces, `suggest/` runs the weekly
  round, `sales/` the daily sale check, `returns/` the return terms

## Adding pieces

Put each piece on a row of `build/pieces_to_add.csv` (the columns are documented at the top of
`build/add_pieces.py`) and run `python3 build/add_pieces.py`. For a Shopify store the price, description,
fabric line and first photo come from the store; for any other store give `price` and `img` too. Rows already
in the closet are skipped, so the file doubles as the record of what was added. Categories: Shirts,
Tees & Polos, Knitwear, Trousers, Jeans, Shorts & Swim, Jackets & Coats, Suits & Blazers, Shoes, Accessories.
Occasions: `work` (For work trips), `dance` (For dancing with friends), `hang` (Hanging out), `dinner` (Going out
to eat), `dressy`, `exercise` (For exercise).

To change a piece later, edit its entry in `build/extras.json` and run `python3 build/make_data.py`. To remove
one, delete the entry and its photo in `images/full/`.

## Things you might want to change

- Names, every sentence on the page, the email address: `config.js`. `email.bcc` quietly copies an address on
  every emailed list; leave it `""` to stop.
- Colours and fonts: `theme.css`.
- The categories, colour families and price bands are the closet's vocabulary and sit at the top of `app.js`
  (`CATEGORY_ORDER`, `COLOR_ORDER`, `COLOR_SWATCH`, `PRICE_BANDS`); `build/add_pieces.py` mirrors the first two.

## New ideas

A "Based on your likes" tab above the grid offers a handful of pieces from beyond the closet, chosen against
the hearts and passes. Adding one hearts it and it joins the grid; passing it removes it. The ideas live in
`suggestions.js`, built from `build/suggest/round_*.json`; `build/suggest/README.md` explains how a round is
run and how brands are vetted in `build/suggest/brands.json`.

## Schedules (GitHub Actions)

- **Weekly round** (`.github/workflows/round.yml`): Saturday 04:17 UTC stage 1 reads the notebook, sweeps the
  approved brands and writes a shortlist to `build/suggest/pending/`. A Claude Code routine may then judge it
  and open a pull request; if nothing has been opened by 17:23 UTC, the fallback picks by score and opens the
  pull request itself. Since 2026-09-26 the pull request merges itself, so each week's ideas publish without a
  review; the pull request stays as the record, with photos. Run by hand from the Actions tab.
- **Daily sale check** (`.github/workflows/sales.yml`): 08:41 UTC, writes `sales.js` with two separate signals.
  *Items*: closet pieces actually marked down right now, matched by product handle in the store's feed; these
  get an "On sale · now $X" pill and a "Marked down right now" filter. *Events*: stores running a real online
  sale event, named in the banner and dotted in the brand list. A permanent sale rack counts as neither. Stores
  without a Shopify feed can only be checked for events. Flags expire if the check is older than three days.
  The same run watches each store's return-policy page and records changes in `build/returns/changes.json`.

## Hearts, passes and the notebook

- The heart saves a piece; the ✕ on a card (or "Not for me" in the detail view) tucks it out of sight.
  Passed pieces collect in a "Not for me" section at the bottom of the Refine panel.
- Both lists live in the browser and in the share link (`#saved=…&passed=…`), and "Email me my list" opens a
  pre-written email with every piece and the link.
- Optional cross-device sync: `sync/SETUP.md` explains how to deploy `sync/Code.gs` as a Google Apps Script
  web app backed by a Google Sheet. Paste its URL into `config.js` as `syncUrl`. With the URL empty the site
  behaves exactly as before. On localhost the notebook is always off.

## Return terms per store

`build/returns/retailers.json` holds each store's return window, who pays return shipping, exceptions and the
policy URL, as stated for US orders, with a `checked` date. `python3 build/returns/make.py` writes
`retailers.js`. The site shows a "Returns at …" line in every item's detail view and lists all stores behind
the storefront count in the About dialog. After any change: edit retailers.json, bump `checked`, run make.py,
commit retailers.js.
